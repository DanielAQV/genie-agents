## 무엇을 만드는가

개발팀장 한 사람(팀원 3명, 본인 포함 4명)을 **따라붙는 비서**.
Slack · GitHub · Figma · Claude Code 로 일하고, 도메인이 많아 놓치는 것이 생긴다.

하는 일은 셋이다.

1. **안 놓치게 한다** — 열린 고리를 든다
2. **찌른다** — 멈춘 것을 제때 올린다
3. **성과로 만든다** — 닫힌 고리를 모아 회고 한 장

### 열린 고리 네 종류

| | 왜 중요한가 |
|---|---|
| 내가 한 약속 | "이거 내일까지 볼게" |
| 남이 나에게 건 것 | 리뷰 요청 · 멘션 · 답 기다리는 스레드 |
| **내가 남에게 건 것** | 팀장 일의 절반. **제일 잘 샌다** |
| 멈춘 것 | 닷새 된 PR, 안 움직이는 이슈 |

## 제일 중요한 전제

> "내가 내 업무를 따로 기록하지 않고 머릿속에 넣는 경우가 많아서"

**이걸 문제로 보지 않고 전제로 놓는다.**

  사람에게 "적어 두세요" 를 시키는 순간 이 물건은 안 쓰인다 — 적을 사람이면
  애초에 이게 필요 없었다.

★ 사람이 하는 일은 **틀린 것을 한 번 눌러 고치는 것**뿐이다.

### 사람은 이미 기록하고 있다 — 다른 이름으로

머릿속에 있는 일도 손은 흔적을 남긴다. 그걸 읽는다.

| 흔적 | 잡히는 것 | 사람이 들일 노력 |
|---|---|---|
| 본인이 Slack 에 친 말 | "내가 볼게" "확인해봐" "내일까지" | 0 |
| 남에게 건 것 | 팀원 3명에게 시킨 것 | 0 |
| 답이 끊긴 것 | 멘션·질문 중 본인 쪽에서 멈춘 것 | 0 |
| GitHub | 내 PR · 나에게 온 리뷰 요청 · 담당 이슈 · 멈춘 것 | 0 |
| 커밋 | 실제로 나간 것. **성과 보고의 근거** | 0 |

## 짧은 말 문제 (그리고 왜 목소리는 안 딴다)

> "종종 내가 짧은건 '다 확인했어' '확인해봐' 등등으로 말하는 경우가 많거든"

**짧은 말은 정보가 없는 게 아니라 정보가 옆에 있는 것이다.**

"다 확인했어" 에서 *무엇을* 은 그 문장에 없지만 **그 자리**에는 있다.

- 스레드 안 → 스레드 원글
- 특정 메시지에 대한 답 → 그 메시지
- 팀원A 와의 DM → 방금 A 가 올린 것
- 채널에서 누가 PR 링크 올린 직후 → 그 PR

Slack 메시지는 `thread_ts` · `channel` · 직전 대화를 다 싣고 온다. 가리키는
대상은 **거의 항상 가장 가까운 앞의 것**이고, 이건 규칙으로는 잘 안 되지만
모델은 잘한다. 팀원들이 그 말을 알아듣는 이유와 같다.

### 오히려 짧은 말이 제일 센 신호다

긴 설명은 배경이고, **짧은 말이 상태를 바꾸는 순간**이다.

| 친 말 | 무슨 일 |
|---|---|
| "다 확인했어" | 고리가 **닫혔다** |
| "확인해봐" | 상대에게 고리가 **열렸다** |
| "내가 볼게" | 나에게 고리가 **열렸다** |
| "이거 좀 봐줄래?" | 상대에게 열렸다 + 나는 기다리는 중 |

동사가 **상태 전이**를, 자리가 **대상**을 나른다.

★ **목소리는 안 딴다.** 습관을 바꾸는 일이라 최소변화 원칙에 어긋나고,
  무엇보다 필요가 없다. 말투는 그대로 두고 옆을 읽는다.

## 틀렸을 때 되돌리는 값이 싸야 한다

에이전트는 틀린다. 그래서 고치는 길을 **탭 한 번**으로 둔다.

- **Slack 이모지** — 📌 이건 열린 고리다 / ✅ 닫혔다. 있던 자리에서, 창 안 바꾸고
- **봇 방에 한 줄** — "그거 됐어" / "그건 내 일 아님"

새 앱도 새 습관도 새 양식도 없다.

### 확신을 같이 든다 (`sure`)

| | 뜻 | 어떻게 쓰나 |
|---|---|---|
| `sure=True` | 명시적이다 | **먼저 말을 걸어도 된다** |
| `sure=False` | 추측이다 | **먼저 말 걸지 않는다.** 하루 한 번 훑는 목록에만 |

★ **먼저 말할 때는 좁게, 훑을 때는 넓게.**
  틀린 알림 하나가 깎는 신뢰가 놓친 고리 하나보다 비싸다. 반대로 목록에서
  줄 하나 지우는 값은 싸다.

## 하루 두 번, 30초 — 이게 예산 전부

**저녁** — ★ **"오늘 뭐 했어?" 라고 묻지 않는다.**

```
오늘 이렇게 보여:
· #42 머지됨
· [팀원A] 에게 리뷰 남김
· #38 은 사흘째 안 움직임

```

**목록을 고치는 것은 목록을 만드는 것보다 훨씬 싸다.** 빈 칸 앞에서
"오늘 뭐 했더라" 를 떠올리는 건 노동이지만, 틀린 줄 하나를 짚는 건 반사다.
머릿속에만 있던 것도 이때 딸려 나온다 — "아 그리고 X 도 했어" 한 줄.

**이것이 사람이 넣는 유일한 입력이다. 하루 한 줄.**

## 만드는 순서

1. **열린 고리 원장 (`loops`)** — 골격에 없는 유일한 새 부품. 자격 증명 없이 다 된다
2. **Slack 채널 어댑터** — 신호원. 읽기 → 이모지로 고치기 → DM 으로 말하기
3. **GitHub 소스** — 근거. 토큰 하나면 되고 신호가 구조화돼 있다
4. **아침/저녁 깨어남** — 언제 말을 걸지 판단. 골격에 `run` 루프가 아직 없다

> 원래는 GitHub 을 먼저 두려 했는데 **바꿨다.** 짧은 말("다 확인했어")이
> 신호의 핵심이고 그건 Slack 에만 있다. GitHub 만으로는 시작이 안 된다.

```
genie-agents (골격)        루프 · 정책 · 도구 등록소 · 도구 계약
```

  인격은 각자, 같은 이름의 도구는 어디서나 같게
